# Зенит Аланья — концепция сайта

[Открыть сайт](https://safal207.github.io/zenit-alanya-site/) · [Проверки и публикация](https://github.com/safal207/zenit-alanya-site/actions/workflows/pages.yml)

Независимая концепция для обсуждения с клубом. Светлая/тёмная темы, русский/турецкий/английский интерфейс, обращения футболистов, журнал вымышленного игрока, личный календарь и игры. Форма готовит текст для родителя; сообщения не отправляются автоматически.

## Личный кабинет игрока

[Открыть кабинет](https://safal207.github.io/zenit-alanya-site/player.html). Семья получает прямую ссылку и одноразовый код отдельно. Игрок выбирает логин и пароль. Фото и план доступны после входа с другого устройства. Черновик из локальной версии можно перенести из того же браузера, пока аккаунт пуст.

В проекте Supabase `Zenit Alanya Player` выпускать коды может оператор с доступом к SQL Editor. Для каждого игрока создайте свой код.

1. Сгенерируйте код и его хеш локально. Выполните `python3 -c "import hashlib,secrets; c=secrets.token_urlsafe(16); print(c); print(hashlib.sha256(c.encode()).hexdigest())"`.
2. Сохраните только вторую строку. Выполните `insert into zenit_private.invites(code_hash, expires_at) values ('HASH', now() + interval '14 days');`.
3. Передайте семье первую строку отдельно от ссылки. Храните её вне репозитория и общих чатов.

Миграция и исходник функции хранятся в `supabase/`. Для браузера используется publishable key. Административный ключ доступен только функции на сервере.

## CI

Каждый push в main, pull request и ручной запуск проверяет:

- 31 контракт логики, реальный ответ Stockfish и 17 сценариев физики и футбольного кубка Babylon/Havok;
- 10 HTTP-проверок, ссылки, лицензии, размер и целостность файлов;
- 103 браузерных сценария Chromium/Firefox/WebKit, включая 14 сканирований доступности и адаптивную вёрстку; 2 проверки разрешения буфера обмена явно пропущены в Firefox/WebKit, отказ в копировании проверяется во всех движках;
- базовые проверки безопасности и npm audit;
- Lighthouse: 3 запуска для каждой из трёх страниц на мобильном и настольном профиле.

Публикация GitHub Pages разрешена только после успешного результата всех блоков. После неё отдельная проверка сверяет опубликованные HTML/CSS/JS с проверенным набором файлов и запускает шесть браузерных сценариев на публичном адресе: фон, обращение и копирование, видео, журнал, навигация и шахматы. PR не публикует сайт. Отчёты, снимки ошибок и трассы сохраняются на 14 дней в Artifacts соответствующего запуска.

Подробные команды, пороги и ограничения: [qa/README.md](qa/README.md). Автоматическая проверка не заменяет реальные iOS/Android, полный аудит WCAG, нагрузочное тестирование или пентест. Звонки и сообщения администраторам не выполняются.

## Файлы публикации

`site.zip` хранит проверенную основу с тяжёлыми медиа и библиотеками. Изменённые исходники и шрифты находятся в `site/`. `site-manifest.json` задаёт точный окончательный набор файлов, их размеры и SHA-256. Скрипт сборки сверяет архив, каждый исходник и общий отпечаток, затем создаёт новый `dist/`. На Pages отправляется только этот каталог; инструменты тестирования туда не попадают.

Локальная подготовка чистой копии:

```sh
python3 qa/unpack-site.py
npm ci --ignore-scripts
npm test
npm run test:http
```

Фактический статус нужно смотреть у конкретного запуска Actions и коммита. Наличие конфигурации само по себе не означает, что проверки прошли.
