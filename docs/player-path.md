# Путь игрока в личном кабинете

Отдельная страница `player.html`, доступная через кнопку «Личный кабинет» в шапке и мобильном меню. Семь ориентиров развития открываются без входа; личная цель, направление, дата пересмотра, подготовка и разбор сохраняются после входа в существующий аккаунт.

`journey_plan` — личный JSON-план в `zenit_player_profiles`: `version`, `stage`, `target`, `review`, `practice`, `reflection`, `actions`. Сервер принимает только объект до 4096 байт. Клиент ограничивает категории, длины заметок, даты и действия. Отметки являются самооценкой. Подтверждения тренера, бронирования, приглашения или поступления из них не выводятся.

Новый столбец использует прежние политики чтения и изменения только собственной строки и отдельное разрешение UPDATE для authenticated. Фото и существующие поля сохранены. Вход допускает ровно два рабочих адреса: GitHub Pages и основной Sites. Все остальные origin отклоняются. Регистрация по одноразовому коду сохранена.

## Проверки

- Контракты нормализации, дат, ограничений, трёх языков и отсутствия неподдерживаемых статусов.
- CORS двух адресов, отклонение чужих origin и независимость ответов параллельным запросам.
- На подключённой базе выполнен откатываемый тест с двумя временными синтетическими игроками: запись/чтение своего JSON, невидимость и невозможность изменения чужой строки, отклонение массива и объекта больше 4096 байт. Все временные строки откатились.
- Браузерный сценарий с контролируемым API проверяет сохранение и восстановление плана и фото со второго устройства. Эти тесты не доказывают работу провайдера Auth; хранилище проверено отдельно на подключённой базе.
- Полный статус браузерных проверок и публикации относится к конкретному запуску GitHub Actions.

Эти настройки не изменялись в данной задаче.
